# Rafi 1.0.5 — исправления, безопасность, производительность

Основа: Rafi-v1.0.4-compact-banquet. Сборка Maven и запуск в среде подготовки не выполнялись (нет доступа к зависимостям): синтаксис Java проверен парсером javac, JavaScript — `node --check`. **Проверьте на копии базы.**

## Исправленные ошибки
1. **Аренда зоны не сохранялась.** `finance()` записывал `zoneRental` только при отсутствии строк `BookingZone`, а они создаются у каждой брони. Теперь значение сохраняется всегда.
2. **Гонка при бронировании.** `synchronized` + `@Transactional` не защищали от одновременной записи (коммит происходил после выхода из блока). Теперь замок удерживается на всё время транзакции (`ReentrantLock` + `TransactionTemplate`) для создания, изменения, смены статуса и продления.
3. **Предварительные брони с истёкшим сроком больше не блокируют зону** (см. «Правила занятости» в README).
4. **Открытие старых броней.** Добавлен `GET /api/clubs/{id}/bookings/{bookingId}`; фронтенд больше не ищет бронь через `/search` с лимитом 200.
5. **Печать карточки** показывает все зоны банкета (как PDF).
6. **Лимиты полей:** телефон до 40 символов, примечание до 255, имя до 120. Ошибки валидации возвращаются понятным сообщением (`ApiErrors`), а не общим 500/400.
7. Основная зона брони (`hallId`) теперь всегда совпадает с первой выбранной зоной.
8. Продление просроченной предварительной брони проверяет, что зона ещё свободна.

## Безопасность
- Включена CSRF-защита (cookie `XSRF-TOKEN` + заголовок `X-XSRF-TOKEN`, поле `_csrf` в формах входа и выхода).
- Ограничение числа неудачных входов (`LoginThrottle`).
- Смена собственного пароля: `POST /api/me/password`, кнопка «Пароль» в шапке.
- Сессия: 8 часов, `SameSite=Lax`, `HttpOnly`.
- Загрузка схемы: размеры картинки проверяются до декодирования, максимум 4000×4000 пикселей.
- Из поставки убраны база `data/`, `target/` и `.idea/`; добавлен `.gitignore`.
- Удалены неиспользуемые эндпоинты `checklist` и `kitchen-sent`.

## Производительность
- Проверка пересечений — один запрос (`findOverlapping`) вместо загрузки всех броней зоны и запроса на каждую.
- `availability`: два запроса на весь клуб вместо «зоны × все брони × запрос зон».
- `search`, `history`, `reminders` фильтруют в БД (Specification / производные запросы), а не в памяти. Для поиска по телефону добавлено поле `phoneDigits`; у старых броней оно заполняется автоматически при первом запуске.
- Зоны приходят вместе с бронью (`zoneIds`); календарь больше не делает отдельный запрос `/zones` на каждую бронь месяца.
- Индексы по `club_id`, `starts_at`, `hall_id`, `booking_id`, `phone_digits` создаются при запуске (`CREATE INDEX IF NOT EXISTS`; при ошибке только предупреждение в консоли).

## Порядок в проекте
- Один актуальный `README.md`; старые инструкции — в `docs/history/`.
- Версия в `pom.xml` — 1.0.5.
- Добавлены тесты правил занятости (`BookingRulesTest`).

## Что сознательно не менялось
- Оптимистичная блокировка (`@Version`): без миграции данных она может сломать существующие брони, поэтому отложена.
- Серверный расчёт итоговых сумм и разбиение `index.html` на модули — отдельные задачи с большим риском регрессий без возможности прогнать приложение.
